选关页 · 分三个页面

单项变体 / 混合档 / Mod 各处一页，互不争抢版面。数据与配色取自项目真实来源： 变体清单来自 VariantCatalog（当前 23 个）、配色来自 ThemeManager._DARK。 点击任意变体可看弹窗流程。
线索型 C 全局约束 G Mod

只有单项变体：1 个经典基线 + 8 个线索型 + 7 个全局约束，共 16 张卡片，一屏放得下。

为什么拆页：单项变体总共只有 16 个，卡片平铺是最省事的呈现； 但混合档有 56 个、Mod 数量随玩家加载而任意增长——三种内容的数量和性质都不一样， 硬塞进同一个滚动页只会让「找某一关」变成翻找。拆页后每页都能用最适合自己的排布。
代价：多一次点击才能到达混合档 / Mod；换来的是每页都不再拥挤、不需要滚动。
交叉表解决了什么：当前的混合档只有 7 个（G_i 与 C_i 同序号配对）， 纯粹是因为环形图每条枝干只能挂一个。改成交叉表后，8 线索 × 7 全局 = 56 个组合全部可达， 规则本身就是「约束 + 线索」的正交组合，表结构正好对应它的代数结构。
三张表覆盖全部混合档（141 组）：T3 C 类「结构 × 观测」70 组 + T3 F 类「结构 × 结构」21 组 + T4「结构 × 观测 + 1 守恒」50 组。
口径更新（2026-09-18）：本页下方那张「约束 × 约束」表已废弃——它按 KIND_GLOBAL 配对，会造出「两个守恒同关」，违反 GDD §5.1 硬限制 3（守恒 ≤ 1）。 终版改为上面三张表（守恒单独成表 + 每关至多 1 个）。
已验证：两类组合都经真值查询——G+C 的 56 个在 5×5 / 7×7 全部可行； G+G 的 20 个在 7×7 / 9×9 全部可行（mx+ep 判逻辑冗余不产生，格子置灰； 其余尺寸级不可行由弹窗内的尺寸按钮自动禁用）。
代价：内容量从 7 个混合档变成 76 个（× 5 尺寸 × 3 关）， 关卡仍是首次进入时按需生成并缓存，但整体生成量级上升。
不需要搜索框：表本身就是索引——想找「和骑士有关的组合」看一行，想找「镜像类的」看一列。

Mod 变体独立成页：数量由玩家装了什么决定，不占用内置变体的版面。

Mod 页的两态：未加载任何 Mod 时显示空状态与放置说明； 加载后卡片自动出现，并且按来源分组（Def 数据包 / 代码 Mod / wasm）， 每张卡可显示该 Mod 的算子数量与作者。
好处：内置变体不再被 Mod 挤动位置——玩家装 3 个 Mod 还是 30 个， 「经典 / 线索型 / 全局约束」那几页永远长一个样，肌肉记忆不会被破坏。

按项目当前布局公式 1:1 复现（1280×720 设计分辨率、23 节点、紧凑内边距）。节点尺寸即游戏里的真实尺寸。
