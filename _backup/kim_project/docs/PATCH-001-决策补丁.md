# PATCH-001（2026-08-25）：开工前四项关键决策

> 来源：用户开工前决策问答（本仓库工作区），效力与正文相同，覆盖《世界扫雷开发 1.0》正文相关条款。
> 配套：开发总纲原文归档为 `docs/世界扫雷开发1.0.md`（如复制失败则以桌面原版为准）。

## 1. 「?」格子玩法：全局强制必开（覆盖 §3.2 / §3.4 可选遮蔽口径）

- **裁决**：「?」玩法每一关、每个变体强制启用，不再是可选遮蔽。
- **替换率下限（PATCH-001a，2026-08-25 修订）**：每关 `?` 格数量下限由 `max(2, ⌊R·C·5%⌋)` **放宽为 `≥1` 个**；上限沿用 §3.4 的 15%。修订原因：现有关卡数据以 1~2 个 `?` 格为主，强制 ≥2 需返工全部关卡。
- **候选池**：沿用 §3.4 —— 全盘安全格（不含雷格），(revealed ∪ hidden) ∩ 雷位 = ∅ 校验不变。
- **? 初始格限量**：沿用 §3.4 —— `≤ max(1, ⌊初始格数/3⌋)`。
- **例外（待 P1 变体逐个落地时另行裁决）**：文档既有限制保留——FR 的 ∞ 格跳过 ?、HV v1 双值线索不支持 ?、脚本规则 v1 不支持 ?。P1 落地到对应变体时以补丁形式给出最终裁决。
- **验证影响**：`test_levels_solvable` 与 `test_oracle_3x3` 的谜题均须包含 `?` 格；`?` 格（hidden_value 档）零信息不计入"开局可确定格"的条款（§9.3）不变。

## 2. 生成器实现：移植为 GDScript（覆盖技术栈相关条款）

- **裁决**：生成器参考 MinesweeperVariants 的"生成答案板 → 动态删线索 → 唯一解校验"算法，**全部移植为 GDScript + RNGService**，游戏内实现，零 Python 依赖。
- 文档 §2.1 决策表、§3.4 确定性契约、第四章 P0 铁律（RNGService P0 仅用于自检）不变。
- 随机生成（含 first-click-safe 延迟布雷）仍按原计划推迟到 P1。

## 3. 目标平台：仅 Steam（首发单一平台）

- **裁决**：首发仅 Windows + Steam（GodotSteam，P5 实装）。
- P0~P4 全部本地 `user://` 开发不变；P5 接 GodotSteam 成就 / 云存档 / 创意工坊 UGC。
- 不承诺 macOS / Linux / 移动端；`user://` 路径与存档结构不得依赖 Steam API（离线分层 §9.2 不变）。

## 4. 创意工坊：P3 + P4 全做（声明式 Def + WASM 沙箱）

- **裁决**：工坊一期（P3 声明式规则包 + custom 拓扑）与工坊二期（P4 godot-wasm 脚本沙箱）**均纳入本作范围**。
- P0 阶段追加一项 spike 任务：验证 godot-wasm 插件在 Godot 4.7.x 下的可用性（安装、`host.tick()` 导入、16MB 内存上限检查），结论作为 P4 排期依据。
