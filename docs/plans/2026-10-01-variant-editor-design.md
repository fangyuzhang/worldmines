# 变体扫雷编辑器（Variant Editor）设计文档

日期：2026-10-01　状态：已定案，按阶段实施中

## 0. 一句话设计

**不新造引擎，只做「数据 + 面板」**：棋盘/邻域/规则/线索全部落成**一个 JSON 文档**，
复用本仓已有的拓扑层（`AdjacencyGrid`）、声明式规则规格 v1（`SpecSchema`/`SpecRulePlugin`）、
求解器（`RuleCpSat` / `BruteForceOracle`）与校验器（`LevelValidator` / `LevelLoader`），
编辑器只是一个**把该文档可视化编辑并即时验证**的 UI 外壳。

## 2. 关键决策（含被否方案与理由）

- **决策 1：环绕边界与自定义邻域都走「邻接表」路线，不改 `RectGrid`。**
  `RectGrid.get_neighbors` 的边界检查同时被「线索计算 / 0 值扩散 / 生成期邻域 / 提示 / 渲染高亮」引用，
  改它等于在五处同时引入边界语义分歧；而 `topology` 路线已被本仓全链路支持
  （`core/board.gd:164`、生成器、CP-SAT、渲染全部按 `GridInterface` 工作）。
- **决策 2：规则一律用 spec v1（JSON）表达，不为编辑器新增"专用规则类型"。**
  spec 已是「数据驱动 + 可存读 + 可校验 + 可求解」的完整链路；编辑器只写 JSON。
  唯一缺口是 clue 表达式不支持线性偏移（`CLUE_EXPR_TYPES` 缺 `lin`），属**小扩展**而非新机制。
- **决策 3：格子类型采用「已有语义 + 预留位」，不发明无玩法语义的新机制。**
  空地/雷/旗/未知已被 `Cell.State` + `is_mine` 完整表达；「障碍」用**洞**（格不存在）表达
  （生成/求解/渲染已原生支持，见 `ShapeGenerator.build_holed_grid`）；
  「传送门/区域」只在文档 `custom` 区**占位声明**，不接玩法（YAGNI，避免半成品语义污染核心）。
- **决策 4：验证器复用 CP-SAT 三接口，不新写求解器。**
  四态判定与三重上限都是现成的；无 C# 后端时降级到 `BruteForceOracle`（`MAX_COMBOS` 上限）并**如实报「未知」**。
- **决策 5：不生成复杂 UI 框架。** 左右面板用 `PanelContainer` + `VBoxContainer` 直排，
  工具按钮复用 `UiTheme.ICON_PAD` / `UiTheme.bind_hover`，不引入抽象层。

## 3. 数据格式（编辑器 ⇄ 关卡 JSON）

### 3.1 棋盘与邻域

```jsonc
{
  "topology": {                       // 缺省 = 普通矩形盘（走 RectGrid，与今天一致）
    "positions": [{"x":0,"y":0}, ...],
    "neighbors": {"0,0": ["1,0", "0,1", ...], ...},   // 形态 2（setup_from_topo 优先）
    "style": "custom",
    "editor": {                       // 编辑器回读用（渲染不读它，避免污染 style_params）
      "wrap": true,
      "include_self": false,
      "dirs": [{"x":-1,"y":-1}, ...]
    }
  }
}
```

环绕实现：`n = fold(pos + dir, size)`，`fold(v, n) = ((v % n) + n) % n`
（GDScript `%` 对负数返回负数，必须补正）；邻居按 `(y, x)` 升序 + 去重，保证**跨会话稳定**。

### 3.2 格子类型

| 编辑器格型 | 落盘表达 | 玩法语义 |
|---|---|---|
| 空地 / 未知 / 旗帜 | `Cell.State`（REVEALED/HIDDEN/FLAGGED/QUESTION） | 已有 |
| 地雷 | `mines[{r,c}]` / `Cell.is_mine` | 已有 |
| **障碍** | 该坐标**不出现**在 `topology.positions` 中（洞） | 已有（不可进入、不可布雷） |
| 传送门 / 区域 | `custom.warp_points` / `custom.regions`（**仅声明，无玩法**） | 预留 |

### 3.3 规则

```jsonc
{
  "clue_rule": "spec_my_variant",     // 已注册的规则 id
  "custom": {
    "schema_id": "editor/v1",
    "spec": { /* spec v1 JSON 原文，随关卡同行以便分享 */ }
  }
}
```
载入时若 `spec` 未注册则按 `register_from_json` 注册（失败不留痕、id 前缀 `spec_` 强制唯一）。

## 4. 验证器四态与上限

| 结论 | 判据 |
|---|---|
| **存在逻辑矛盾** | `is_feasible() == false`（或 `count_solutions() == 0`） |
| **唯一解** | `count_solutions() == 1` |
| **无需猜测可解** | 唯一解 + 序贯 `find_forced_cells()` 传播直至通关（每轮推进数 > 0） |
| **可能需要猜测** | 传播停滞（两数组皆空）且仍有未开格 |
| **未知** | CP-SAT 不可用 / 触达预算（时间或节点）——**如实报未知，不猜** |

上限：`RuleOracle.probe_budget_ms/core_budget_ms`（时间）、`BruteForceOracle.MAX_COMBOS`（节点）、传播轮数上限（编辑器显式传入）。

## 6. 风险与纪律

1. **`supports_topology()` 纪律**：拓扑盘上必须走 `compute_clue_topo`；若某规则只声明 `GEO_ADJ_GENERIC` 却不覆写，
   其线索值必须恰为邻域雷数（`core/rule_plugin.gd:140-157`）。编辑器「规则面板」要**显式提示**这一点。
2. **`refs:"topo"` 索引序**：适配器已固定为 `(y,x)` 升序（跨会话稳定）；编辑器生成的邻接表也用同一序，
   两处一致 ⇒ 不会出现"生成期验证过、载入后不可解"。
3. **性能上限**：画布格数上限与加载器同口径（`LevelLoader.MAX_CELLS = 64*64`）；
   预览线索为 O(格数 × 度数)，编辑期内只对**被改动的格**增量重算（避免每次全盘）。
4. **打包面**：新增运行时资源（模板/示例）必须进 `export_presets.cfg` 的 `include_filter`；
   新增工具脚本落在 `tools/`（已被 exclude 覆盖）；新增 `.ps1` 必须 ASCII-only 且用 `CliShutdown` 退出。
5. **不做的事（YAGNI）**：不接 Steamworks 真实上传、不给传送门/区域定义玩法、不做多人协作、不做脚本化规则编辑器
   （spec v1 已覆盖"改邻域/改线索"；更复杂的规则仍走 `entry.gd` 手写插件，文档已有指引）。

### 8.1 实现期发现并修掉的缺陷（每条都有证据，不是"顺手清理"）

1. **CI 盲区（最有价值的一条）**：测试脚本**解析失败会被 GUT 静默跳过**，门禁照样报 GREEN——
   而且是"用例数与改动前**一模一样**"这种最难发现的方式（新增文件根本没跑）。已在 `ci_check.ps1`
   加两道检查（磁盘 `test_*.gd` 数 == GUT 收集数；日志不得含 `Parse Error`），并做了**负向验证**。
2. **Risky 假测试**：断言写在"遍历空集合"的循环里 ⇒ 一个断言都没执行，GUT 仍算通过
   （新增的 `[Risky]` 门禁当轮就抓到了我自己写的一条）。
   ⇒ 门禁口径同时校正：`Risky` 判红（不会失败的测试等于没有保护），`Pending` 按本仓既定政策不判红
   （GUT 在"全通过但有 pending"时不打横幅，旧判据会因此误报）。
3. **`rule_object()` 幂等缺陷**：用户一按「试玩」把规则注册进全局表，
   `SpecSchema.validate` 的"id 必须全局唯一"就会让预览报"规则未解析"——
   **一按试玩预览就坏**。已改为仅对"同名 id 已注册"这一种失败兜底，其余失败照实报错。
4. **外部拓扑数据丢失**：载入六边形/三角等外部盘后按 `dirs/wrap` 重建 topology，
   会把盘型**静默换成方阵**（不可逆）。已改为原样保留 + 明确告警。
5. **不可行判定产生假 ERROR**：C# 求解器对"不可行"这一**正常结论**打 `ERROR`，
   被 GUT 记为 Unexpected Errors、也会污染发行版日志。已加**廉价必要条件预检**
   （声明雷数 > 可能雷格数 ⇒ 逻辑矛盾），毫秒级出结论且不碰求解器。

### 7.3 收口复查又补的两件事（2026-10-02 晚）

1. **拓扑盘"值接了、扩散没接"的半接线补齐**：新增可选契约
   `RulePlugin.zero_safe_neighbors_topo(pos, topo, value)`，把 `core/board.gd:_flood_neighbors`
   里那段硬编码"0 值 ⇒ 全部拓扑邻格"**搬进契约**（计数型逐位不变），

### 7.5 第三轮复查（2026-10-02）：性能与内存两个实测出来的隐患

用临时探针量了"编辑器改一格"的真实成本（64x64 / 400 雷，探针用完即删）：

| 步骤 | 默认矩形盘 | **环绕盘（要建邻接表）** |
|---|---|---|
| `topology()` | 13 µs | **48.9 ms** |
| `validate()` | 0.92 ms | **368 ms** |
| `preview_clues()` | 21.1 ms | **101 ms** |
| `grid()` | 5.8 ms | **91.5 ms** |
| **合计 / 改一格** | 27.9 ms | **609.7 ms** |

⇒ 环绕大盘上画一笔约 **0.6 秒**，直接违反"不能因为棋盘稍大就卡死"。根因：`WrapTopology.build`
与 `AdjacencyGrid.setup_from_topo`（要逐条 `String.split(",")` 解析约 32k 个邻居键）**每次调用都重跑**，
而 `validate()` / `preview_clues()` / `grid()` 各自还会再建一遍。

**修法（三件，均带回归测试）**：
1. **结构签名 + 缓存**（`EditorDoc.struct_signature()` / `topology()` / `grid()` / 审计结果）：
   内容变 ⇒ 签名变 ⇒ 自动失效。选"内容摘要"而不是"要求调用方记得 invalidate"——后者漏一次就是幽灵 bug。
2. **增量预览** `preview_cells(cells)`：编辑器改一格只重算"该格 + 其邻居"（≤9 格）。
   与全量预览共用 `_clue_value_at` ⇒ 两条路径不可能算出不同的值（由测试钉住）。
3. **昂贵检查去抖 260 ms**：拓扑审计/结构校验/全量预览合并到空闲时跑；编辑路径只剩增量重算。

**修复后同口径实测**：增量预览 **87 µs**（与全量逐值一致：不一致 0 个）、`grid()` 12 µs、
全量预览 10.6 ms（`grid()` 复用缓存后省掉 91.5 ms）⇒ **编辑路径 ≈0.1 ms/格（约 6000×）**；
拓扑重建（51 ms）与审计（~190 ms）只在**结构变更**时付一次，且已去抖。

**同轮发现的第二个隐患（内存）**：撤销快照用的是 `to_level_json()`，它**包含 topology**
（64x64 环绕盘展开数 MB）⇒ 50 步撤销 = 上百 MB。改为 `EditorDoc.snapshot()/restore()`：
只存编辑状态，派生的 topology 由结构字段重算；外部拓扑存**引用**（会话内只整体替换、从不原地改）。
⚠ 落地时的坑（被同一批测试当场抓到）：`wrap` / `dirs` / `include_self` 虽然**是真源**，却写在
关卡 JSON 的 `topology.editor` 元数据里、障碍更是"positions 里没有谁"反推出来的 ⇒ 省掉 topology
就必须**显式**把结构源也存进快照，否则恢复出来的是"方阵 + 无邻域 + 无障碍"。

### 7.7 第五轮：零代码创作路径（2026-10-02，P5）

**目标**：让**不写代码**的玩家也能做变体。真实可行的路径不是"给他一个 JSON 编辑器"，
而是：**玩家用一句日常语言说想法 → 交给他自己电脑上的 AI（DeepSeek/豆包/ChatGPT）→
AI 回一段 JSON → 玩家把整段回复粘回编辑器 → 编辑器读懂、校验、立刻能用**。

| 交付 | 关键点 |
|---|---|
| `core/spec_helper.gd`（纯逻辑，无 UI） | `ai_prompt` 生成**自包含**提示词（对方的 AI 看不到本仓库 ⇒ 字段表/原子表/硬约束/做不到的事/两个可照抄的示例/输出格式必须全写进去），并按当前棋盘**直接指定该用哪种 geometry**；`extract_json` 宽容解析；`kind_of` 分流；`explain_spec` 说人话；`friendly` 报错白话化；`repair_prompt` 让 AI 自己修；`recipes` 零 AI 兜底 |
| 编辑器「AI 帮我写」页（第 2 页） | 三段式：复制「给 AI 的话」→ 粘回复 → 一键导入；失败时「让 AI 修」按钮把报错交回给 AI；同页有 6 条现成配方 |
| `tools/spec_check.gd --prompt` | 命令行取**同一份**提示词（与界面复制的内容由同一个函数生成，不会两处话术不一致） |
| `core/editor_doc.gd` 新增 `topo_needs_table` 告警 | 见下方"发现 1" |

**发现 1（真静默坑，本轮最重要的技术发现）**：`refs="topo"` 的规格在**普通方阵盘**上数字会**全是 0**。
`SpecRulePlugin.compute_clue` 对该形态返回 `empty_value`（`core/spec_rule_plugin.gd:151-156`），
而普通方盘走 `RectGrid` ⇒ 平台调的正是 `compute_clue`。这与"端到端缺口已修"**不矛盾**：
缺口的四处接线（生成/载入/显示/验收）都在 `compute_clue_topo` 那条路径上，前提是**棋盘真有邻接表**。
零代码路径最容易踩它（用户会说"让 AI 写个相邻格的规则"，AI 用 `refs="topo"`，方盘上得到满屏 0）。
处置：提示词按盘面**指定**写法 + 配方卡写明适用盘面 + `EditorDoc.validate()` 发 `topo_needs_table`
告警并给三条出路（开环绕 / 换形状盘 / 改固定方向 + rect_only）。

**发现 2（工具纪律）**：`JSON.parse_string` 在解析失败时会 `ERR_PRINT`，而"替用户试读他粘进来的东西"
里读不懂是**常态** —— 本仓 GUT 把引擎错误记为测试失败，这条纪律被新测试当场抓到。
处置：`SpecHelper.parse_json_safe()`（`JSON.new().parse()`，静默返回错误码），并顺手把编辑器里两处
同类隐患（`_on_rule_changed` 打字中途、`_load_from_text` 粘错东西）一并换掉。

**发现 3（文档自相矛盾）**：《变体规则编写规范》§12.4 仍写着"`refs="topo"` 只在生成侧可用、
先别落盘发布"，而该缺口早已修好（§12.3 自己写了"已退役"）。两份说法同时存在时，**下一个 AI 会照着错的那条做**。
处置：§12.4 改写为"四处已接通 + 唯一前提是棋盘要有邻接表"；§12.5 去掉 `e2e_gap` 的判级说明；
`tools/spec_check.gd` 里两处过期注释同步更正；§12.6 升级为一键提示词路径；新增 §14.8。

**裁定（明确不做）**：不接"一键用规则生成一关"按钮。`generate_with_rules` 会调 CP-SAT（可能数秒无响应）、
且在无 C# 后端时返回空 ⇒ 对小白是"点了没反应"。零代码路径改用零风险闭环：
导入规则 → 数字立刻重算 → 随机布雷 → 试玩 → 验证页判定。生成关卡仍由现有 `spec_check --generate` / 游戏侧负责。

1. **必须用集文件，不能一关一文件**：安装侧上限 `MAX_INSTALL_FILES=64`（`workshop_pack.gd`），100 关一关一文件必然撞墙 ⇒

### 7.11 第九轮：真机目视（P7 收尾）—— 一次走查抓到 4 个"测试全绿但用户用不了"的问题（2026-10-02）

**为什么这次值得单独记**：CI 1039 条用例全绿、黄金网全套逐字节不变，但把编辑器真正跑起来点一遍，
仍然连着抓到 4 个缺陷 —— **它们没有一个能被单测覆盖**（都是"布局/尺寸/窗口"这类只有真机才现形的东西）。

| # | 真机现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | **「批量生成关卡」在首屏之外**（左栏内容已 ≈2 屏高，要滚约 1.5 屏） | 左栏按功能顺序增长，批量入口排在"存档与分享"之后；小白不会去滚一个看不出有内容的侧栏 | 四步条正下方加首屏入口「要做很多关？→ 批量生成关卡」；原分组保留 |
| 2 | **「开始生成/停止/关闭」在 720px 屏幕之外**（点不到开始） | 弹窗内容 ≈830px；更关键的是 **Godot 里 `Control.size ≥ combined_minimum_size`**，而**自动换行 Label 在窄宽度下把最小高度算成 1023/1239px**（真机实测），内容最小高度 1322 ⇒ 窗口永远压不回 680。`wrap_controls=false` 与"每步夹屏"都救不了它（压的是窗口，撑住的是最小尺寸） | ①内容进 `ScrollContainer`、**按钮行与进度区留在滚动区外**；②**给自动换行标签钉死换行宽度**（`custom_minimum_size = Vector2(620, 64)`）⇒ 最小高度回到几行，窗口才压得住；③`popup_centered_clamped` + 每步夹屏（用**父窗口**居中居中） |
| 3 | **81 关、5 分 28 秒全白生成**，然后"打包失败：文档未通过校验：雷数 81 ≥ 可用格数 81" | 批量打包走 `WorkshopPack.build(doc, …)`，它先拿**编辑器当前打开的那张盘**跑校验；而批量包的内容是 `levels/<大小>/<档位>.json`，与当前盘无关 | 批量模式（有 `levels_dirs`）**跳过"当前文档校验"**，并且不把"当前盘"的 `board.json`/`preview.png` 混进批量包（单关包老路径不变） |
| 4 | 我自己引入的坐标错误：弹窗被甩到游戏窗口之外 | `_forge_fit_window()` 用**物理屏幕坐标**（`screen_get_usable_rect`）居中，而 MCP/输入坐标系是游戏窗口坐标 ⇒ 点"开始生成"落在窗口外的画布上，`exclusive` 弹窗判定"点了外面"自行关闭 | 改用**父窗口**居中：`Rect2i(get_window().position, get_window().size)` |

**可复用的教训（已同步进《变体规则编写规范》§14.9）**：
- 弹窗里的**自动换行 Label 必须钉死换行宽度**，否则会在窄宽度下爆出上千像素的最小高度，把窗口顶到屏幕外；

- **批量操作不许被"编辑器当前状态"绑架**：批量产出与当前盘无关，就不该拿当前盘去校验它。
