# 难度体系设计（v1 · 定稿待实施）

> 日期：2026-09-19　状态：设计已定，待实施确认
> 背景：交叉验证证明现行难度 = 长度分（与步数秩相关 **0.923**、与深度仅 **0.475**，见 `难度体系_对标选型与升级方案.md` §7）。
> 本设计以难度为核心重定「什么算难、怎么定档、供哪些档、用户自建变体怎么办」。**推翻的是难度这一层，不是生成器与规则体系。**

---

## 0. 决策摘要（一句话）

**难度 = 推理深度（单步最大必要线索数 peak），用全局绝对窗口定档（入门≤2 / 正常3–4 / 困难5–8 / 噩梦9–20）；长度与规则学习成本作为独立标注，不混入难度；供给按「实测可达性」决定供哪些档，不硬造；用户自建变体零配置可用（跑 profile 即定档）。**

---

## 1. 为什么是这套（数据依据）

样本：服务器全部产物 **52,988 关**（30+ 批次，含 o1–o10 / s1–s6 / z1 / z4，工具 `tools/difficulty_quantiles.sh`）。

| 事实 | 数据 | 推论 |
|---|---|---|
| 峰值分布（全局分位） | P40=2 / P70=5 / P90=9 / P95=11 / MAX=30 | 深度轴有真实梯度，可支撑四档 |
| 四档窗口占比 | 入门 44.1% / 正常 22.8% / 困难 21.7% / 噩梦 11.1% / 超纲(≥21) 0.3% | 天然金字塔，档位语义与稀缺性同时成立 |
| 峰值随尺寸单调增长 | 5×5 中位 1 → 8×8 中位 5 / 最大 24 | 尺寸是难度的自然组成部分（与对方同构） |
| 深度与长度近似独立 | 短而深（steps≤2 且 peak≥7）645 关；长而浅 163 关 | 「深度定档 + 长度画像」成立，不会重演长度混入难度 |
| 变体间差异巨大 | 噩梦命中率：o4 42.1% … z1 0.8%、o8/o9 **0.0%** | 绝对窗口跨变体可比；但**供给能力必须按单元实测** |

> 关键取舍：**不做加权成本表、不做分位自标定**。理由：加权表在"用户自建变体"处必然崩（无法预先为未知规则列表）；分位自标定会把 o8 的 peak=1 定义成"噩梦"（相对可比但绝对荒谬）。绝对窗口只依赖**规则无关**的求解器产出，天然同时满足可比性与零配置。

---

## 2. 度量定义（三层，全部已有数据，无需新算力）

| 层 | 定义 | 状态 |
|---|---|---|
| `value(step)` | 该步**必要线索数**（unsat-core 大小） | ✅ 已有（`stats["complexities"]`，每轮一次） |
| `peak` | `max(value(step))` | ✅ 已有（`difficulty_profile.max_complexity`，落盘率 99.1%） |
| `steps` | 总步数（长度，**独立轴**） | ✅ 已有 |

- **不再**用 `difficulty = Σ(1/批量)` 定档；它保留作"紧凑度"排序辅助指标。
- `peak` 的上限：≥21 的盘为"机器级"（实测占 0.3%，152 关）→ 建议**过滤**，不进任何档。

### 2.1 档位窗口（全局统一）

| 档 | 窗口 | 语义 |
|---|---|---|
| 入门 | peak ≤ 2 | 一步一见 |
| 正常 | 3 ≤ peak ≤ 4 | 需要同时把握 3–4 条线索 |
| 困难 | 5 ≤ peak ≤ 8 | 需要组合 5–8 条线索，常见"顿悟点" |
| 噩梦 | 9 ≤ peak ≤ 20 | 需要同时把握 9+ 条线索（实测全局仅 11.1%） |
| （超纲） | peak ≥ 21 | 机器级，过滤 |

### 2.2 两条独立标注轴（不进档位）

- **规模 steps**：短(≤2) / 中(3–6) / 长(7–15) / 超长(≥16) → UI 筛选、排序
- **规则学习成本**（变体级）：每个变体卡片标注"规则理解成本"，由该变体全部单元的实测分位反推（如 z1 全局偏浅 + 规则直观 → 低）；**不参与关卡难度**

## 3. 供给可行性规则（本设计的硬约束）

实测（`tools/difficulty_cost_matrix.sh`）：以现有 5.3 万关为基线，反推"填满一集 100 关所需的生成采样量" → 命中率 = 100/采样量。

| 命中率区间 | 采样量 | 供给策略 |
|---|---|---|
| ≥33% | ≤300 | **主供档**（≈1× 成本，可大批量） |
| 1%–33% | 300–10000 | **辅供档**（按机器预算限量，需定向搜索加持） |
| <1%（含 0） | >10000 或 ∞ | **不供该档**，UI 如实说明 |

### 3.1 实测结果（99 个单元，样本 ≥150）

- **噩梦档 ∞（现产物 0 命中）28 个单元**：`o8@5-9`（全部尺寸）、`o9@5-9`、`o10@5`、`o5x@5`、`s1@5`、`s3@5/6`、`s4@5`、`s6@5/6/7`、`z1@5/6/7/8` …
- **噩梦档 ≤500 采样（优秀）23 个单元**：`o1_9@9`、`o2@7/8`、`o3@7/8/9`、`o1c@8/9`、`o2/3_merged@8/9` …
- **500–3000（可接受）28 个**；**>3000（昂贵）20 个**：`s1@7/8/9`、`s2@6/7/8`、`s4@6/7`、`o2@5` …
- **变体级噩梦命中率**：o4 42.1% → o3b 25.7% → o2 21.7% → o5x 13.0% → z4 6.0% → s6 5.2% → s2 4.0% → s3/s4 1.9% → s1 1.2% → z1 0.8% → **o8/o9 0.0%**

### 3.2 由此得出的供给矩阵规则

1. **不追求"每变体×每尺寸×4 档 ×100 关"的刚性矩阵**（实测 28 个单元连 1 关噩梦都没有；刚性达标需天级时间/格）。
2. 改为**可行矩阵**：每单元供给"可达档位"，总量 = Σ(单元 × 可达档 × 100)（具体量在实施时由成本矩阵生成）。
3. 深变体（o1/o2/o3/o4/o5x + 对应 merged）供全 4 档；中浅变体（s1–s6 / z1 / z4）供入门–困难（噩梦视单元实测）；**o8/o9 只供入门–正常**。

## 4. 无深度梯度的变体（o8 / o9 类）

实测：`o8_zhongdian` 全尺寸 peak ≤2（P90=1）、`o9_sheju` peak ≤3（P90=1–3），全局峰值分位退化。

- **原因**：这两个算子的规则"一步直达"（推理不需要组合线索），深度轴上无梯度。
- **决策**：如实标注"**一步直达型变体：难度由尺寸与规则学习成本表达**"，不硬造困难/噩梦；混合集（与其它算子同盘）深度自然回来。
- **不做**加权表硬抬（加权只能整体平移，造不出梯度 —— 所有步都只有 1 条线索时，加权后仍然全部相同）。

## 5. 生成侧改造（推翻范围，最小化）

| 项 | 现状 | 改为 |
|---|---|---|
| 生成目标 | 标量 `target_difficulty`（走长度语义） | **窗口谓词** `peak ∈ [lo, hi]`（验收条件） |
| 深度计算 | 生成时每轮已算 `complexities`（有开销但已在跑） | 复用，无新增成本 |
| 搜索 | 目标压力 = 删线索减步数 | **把 `peak` 加入验收/评分**（局部改动，非重写） |
| 供给统计 | 按标量档 | 按窗口 + 单元可达性 |
| 存量 | 52,988 关（旧档语义） | **离线重标**（零成本）：可用作入门/正常现成供给 + 标定基线 |
| 导入校验/UI 档位文案 | 按标量阈值 | 按窗口 |
| `board_view` / `level_select` 档位筛选 | Σ1/批量标签 | 窗口标签 + 规模/规则成本标注 |

**保留不动**（与本设计正交）：Mod/规则体系 + 沙箱、`RuleCpSat` 解题器、无猜生成内核、断点续跑、UI/录制。

---

## 6. 用户自建变体（零配置）

1. 用户注册自定义规则（mod）→ 生成器跑出候选 → 计算 `profile` → **按绝对窗口自动定档**（无需作者声明任何权重/参数）。
2. 若某档在该尺寸下不可达（如用户的规则"一步直达"）→ **如实提示**："该变体在 7×7 下无法达到困难档（实测峰值上限 2）"，并建议加尺寸或混合规则。
3. 变体卡片的"规则学习成本"在样本足够后用实测分位自动标注。

> 这是选择绝对窗口而非加权表/分位自标定的**决定性原因**：它是唯一能让"用户设计的未知变体"开箱即用的方案。

---

## 7. 证书与可解释性

- 每关落盘：`peak` / `steps` / `histogram` / 档位 / 档位依据（如"峰值 9：第 4 步需同时把握 9 条线索"）。
- UI 可展示"为什么难"，并为"短而深 / 长而浅"提供区分（防"磨盘冒充难度"）。

---

## 8. 唯一待验证项（探针）

**问题**：把 `peak` 加进验收/评分后，各单元的定向命中率能提升多少？
- 若提升显著（如 s1@8 噩梦命中率 1.2% → ≥10%）→ 中浅变体补上困难档，可行矩阵大幅扩张。
- 若提升有限 → 按 §3.2 的可行矩阵交付（深变体供全档，中浅变体供至困难），不追加投入。

**做法**：`tools/batch_all_variants.gd` 增窗口参数（不改内核）→ 取 3 个代表单元（深 `o4@8` / 中 `s1@8` / 退化 `o8@8`）各跑 200 关 → 记录命中率与单关耗时。

---

## 9. 验收标准

| 项 | 标准 |
|---|---|
| 档位语义 | 任一档的关卡，`peak` 落在窗口内 100%（可脚本校验） |
| 跨变体可比 | 同一档在任意变体的窗口相同（绝对口径），不因变体而异 |
| 可解释 | 每关可输出档位依据；UI 能显示 peak/steps |
| 供给 | 交付矩阵每格 ≥100 关（不可达档位已在 UI 声明） |
| 退化变体 | o8/o9 类不出现"噩梦"标签；提示文案存在 |
| 用户变体 | 新 mod 注册后无参数即可定档；不可达档位有提示 |
| 回归 | 现有测试全绿；存量 52,988 关离线重标脚本可复跑 |

## 11. 与对标文档的关系

- 采纳对方：**深度语义**（单步必要线索数）、**档位窗口结构**（MIN/MAX/顶格步数）、**择优排序**（第二期，RankScore）。
- 不采纳：**加权成本表**（用户变体处崩）、**分位自标定**（语义错位）、**负号与平衡闸**（与守恒轴 Z 冲突）、**离线大池建库**（保留在线生成可扩展性）。
- 修正：对方"噩梦 1.1%"与我们"噩梦 11.1%"是不同尺度的产物，**常量不可直接移植**（详见对标文档 §7.4）。
