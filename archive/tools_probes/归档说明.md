# 归档说明（archive/tools_probes/）

> 2026-09-26 建立。原因：审计发现项目文档里有 **8 处 `tools/_*.py|gd` 引用全部失效**——
> 不是脚本丢了，而是它们已从 `tools/` 移入本目录，**文档没跟着改**。

## 这是什么

`tools_probes/` 是**一次性诊断 / 分析脚本**的归档区。

命名约定：文件名带 `_` 前缀 = **临时工具**（相对 `tools/` 下的正式工具如
`verify_all.ps1` / `verify_batch.gd` / `gen_geo_levels.gd` 等而言）。这些脚本当年
在 `tools/` 下临时写过、用过、然后就留在那儿了，后来统一归入本目录。

## 文档里的路径 vs 实际位置

项目文档（`HANDOFF.md` / `交接文档.md` / `关卡集供给对账.md` /
`难度体系v2_噩梦档供给.md` / `难度体系v2_遮蔽旋钮.md`）里写的 `tools/_xxx.yy`
**是它们当年的位置**。审计核出的对应关系：

| 文档里写的 | 实际在此处 |
|---|---|
| `tools/_add_intro_rows.py` | `archive/tools_probes/_add_intro_rows.py` |
| `tools/_analyze_harvest.py` | `archive/tools_probes/_archive/_analyze_harvest.py`（多一层 `_archive/`） |
| `tools/_diag_clue_ratio.py` | `archive/tools_probes/_diag_clue_ratio.py` |
| `tools/_diag_csv_check.gd` | `archive/tools_probes/_diag_csv_check.gd` |
| `tools/_mixed_version_audit.py` | `archive/tools_probes/_mixed_version_audit.py` |
| `tools/_mixed_version_check.py` | `archive/tools_probes/_mixed_version_check.py` |
| `tools/_plan_gaps.py` | `archive/tools_probes/_plan_gaps.py` |
| `tools/_probe_mod.gd` | `archive/tools_probes/_probe_mod.gd` |

同批归档的还有 `tools/_audit_catalog.py`（`关卡集供给对账.md` 已单独修正路径）。

> **为什么不去逐条改文档**：那 5 份文档多数是**带日期的历史快照**（记录"当时用什么工具得出什么结论"），
> 把路径改成今天的样子反而失真。这里给一份映射，两边都对得上。

## 新读者怎么找脚本

```powershell
# 列出全部归档的 Python 工具
Get-ChildItem archive/tools_probes -Recurse -Filter "_*.py"

# 按名字直搜（不记得在哪一层时）
Get-ChildItem . -Recurse -Filter "_plan_gaps.py" -File
```

本目录共约 320 个文件，含历次审计/诊断/探针脚本及少量 `.log` 产物。

## 注意

- 这些脚本**不是维护目标**：它们反映的是当时的代码与数据结构，直接跑很可能已经不适配
  （字段改名、路径变化、依赖的服务器环境已不在）。**当作阅读材料，不当作可执行工具。**
- 正式、仍在维护的工具在 `tools/` 下，见 `HANDOFF.md` 的「改功能去哪」与「运维脚本」两节。
