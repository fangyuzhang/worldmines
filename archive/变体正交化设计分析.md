# 14 变体正交化重设计方案

> **问题**：现有 7 线索 × 7 全局约束无法随意组合，某些搭配会出现耦合/退化/无解。
> **结论**：**骨架不用换 —— 7+7=14 正好对标《14 Minesweeper Variants 2》。要换的是成员选择，并把组合性从"手写互斥表"升级为"可推导的代数性质"。**
> **诊断依据**：`core/constraint_engine.gd` / `core/clue_engine.gd` / `core/variant_registry.gd` 源码实读 + 全称量化推导。
> **新增代码**：`core/rule_signature.gd`（算子签名与组合性判据，纯增量，不改现有代码）。

## 0. 先纠正一个被沿用的算术笔误

交付文档 `03_规则系统.md §1` 写的是：

> 8 + 8 − 1（共享 `V`）= **14**

`8+8-1 = 15`，这是笔误。看源码常量：

```csharp
LEFT_SETS  = { "V","2H","2C","2S","2G","2F","2B","2T" }   // 8 项
RIGHT_SETS = { "V","2X","2D","2P","2E","2M","2A","2L" }   // 8 项
```

去掉两线共享的底座 `V`，**每线恰好 7 个真变体，7 + 7 = 14**。

**这意味着：本地项目的「7 线索 + 7 全局约束」骨架，在结构数量上已经与 14MV2 完全一致。** 问题不在骨架，在两件事：

1. **成员选错了方向** —— 7 个全局约束里有 6 个是同一类数学对象
2. **组合性靠手写表维护** —— 无法解释原因，也无法增量扩展

## 1. 耦合诊断：四个数学根源

### 根源 1 —— 6/7 的全局约束是同一类数学对象（低维计数投影）

把 7 个约束按「作用在什么数学对象上」重新分类：

| 约束 | 数学定义 | 作用对象 | 类别 |
|---|---|---|---|
| `mx` 镜像 | $B_{r,c} = B_{r,C-1-c}$ | 逐点 | 对称约束 |
| `rl` 相邻行锁 | $\lvert M(r)-M(r+1)\rvert = 1$ | 行 profile | **计数** |
| `pf` 局部禁形 | $\sum_{2\times2} B \le 2$ | 2×2 窗口 | **局部** |
| `qd` 四象 | $Q_0=Q_1=Q_2=Q_3$ | 象限和 | **计数** |
| `dt` 骨牌 | 每骨牌 $\sum B = 1$ | 精确覆盖 | **计数+划分** |
| `ep` 端点平衡 | $C(0)=C(C-1)$ | 列端点 | **计数** |
| `4c` 四向守恒 | $\sum_{(-1)^{r+c}=1}B = \sum_{(-1)^{r+c}=-1}B$ | 染色和 | **计数** |

**只有 `pf` 是局部算子，其余 6 个全是"低维计数投影"。**

所有计数投影共享同一条母线 $\sum B = N$，因此它们**不是代数独立的**：任取两个，其约束矩阵的秩往往不满，产生蕴含关系或直接冲突。

> 对照 14MV2 左线 7 个（`[2H] [2C] [2S] [2G] [2F] [2B] [2T]`）：**全部是局部模式 / 连通性 / 形状**，没有一个是计数投影。这就是它能任意组合的原因 —— 左线压根不碰"总雷数怎么分"。

### 根源 2 —— 严格逻辑蕴含（不是"不搭配"，是"白加"）

现有 `variant_registry.gd:124` 的 `forbid: mx+ep` —— 这不是冲突，而是**冗余**：

> **$mx \implies ep$**
> `_check_mx` 遍历 $c < C-1-c$ 要求 $B_{r,c} = B_{r,C-1-c}$。取 $c=0$ 得 $B_{r,0}=B_{r,C-1}$ 对所有 $r$ 成立，即 $C(0)=C(C-1)$，正是 `ep` 的定义。**严格蕴含。**

> **$mx \implies 4c$（当列数 $C$ 为偶数）**
> $C$ 偶 $\Rightarrow C-1$ 奇 $\Rightarrow c$ 与 $C-1-c$ 奇偶相反 $\Rightarrow$ 镜像把每个雷配到一个**异色**格 $\Rightarrow black = white$，正是 `4c` 的定义。
> **严格蕴含。**（6×6 / 8×8 正是偶数列盘面 —— 所以这两个尺寸下 `mx+4c` 完全冗余。5×5/7×7/9×9 有中轴自映射，不冗余。）

> **$mx \implies$ `qd` 的 3/4 条件**
> $mx \Rightarrow Q_0=Q_1$ 且 $Q_2=Q_3$ 恒成立，`qd` 只剩 $Q_0=Q_2$ 一条有效 → `warn: mx+qd` 的真因。

**结论：`mx` 是一个极强的一阶算子，它把三个二阶计数约束吞掉了。** 这不是设计失误，而是没有把「蕴含」建模进来。

### 根源 3 —— 手性 / 各向异性冲突（线索 × 结构）

这是 C 类组合（一观测 + 一结构）也会退化的元凶。按**对称群**给线索分类：

| 线索 | 数学定义 | 保持的对称群 | 各向同性？ |
|---|---|---|---|
| `classic` `4n` `sc` `distsum` `hv` | 邻域加权计数 | $D_4$（旋转+镜像） | ✅ |
| `loopruns` | 环形 $0\!\to\!1$ 上升沿数 | $D_4$（环序反转不改变段数） | ✅ |
| **`clock`** | 顺时针首个雷的方位编号 | **$C_1$（仅恒等）** | ❌ 手性 |
| **`fr`** | 向右射线到首雷的距离 | **$C_1$** | ❌ 方向性 |

而 `mx` 的结构是**强制左右对称**。于是：

- **`fr` × `mx`**：布局左右对称 ⟹ 右半射线的信息完全由左半决定 ⟹ **线索信息量砍半，退化**
- **`clock` × `mx`**：镜像使环序反向（$2\leftrightarrow8,\ 3\leftrightarrow7,\ 4\leftrightarrow6$）⟹ 两格线索值有确定对应 ⟹ **部分冗余**

> 这就是"没法随意组合"最直接的来源：**两个各向同性的算子可以自由组合，一旦掺入各向异性算子，就必须逐个 case 分析。**

### 根源 4 —— 整除约束与 R07 固定雷数契约打架

计数投影算子的通病：**对总雷数 $N$ 施加整除要求**。

| 算子 | 整除要求 | R07 主值（5×5=10, 6×6=14, 7×7=20, 8×8=26） |
|---|---|---|
| `qd` | $(N - \text{中轴雷数}) \equiv 0 \pmod 4$ | 6×6：$14 \bmod 4 = 2$ ⟹ **UNSAT** |
| `4c` | $N \equiv 0 \pmod 2$ | 全部满足 ✅ |
| `dt` | 完全覆盖时 $N = \lfloor RC/2\rfloor$ | 5×5 需 $12.5$ ⟹ **不可能** |
| `grpk` | $N \equiv 0 \pmod k$ | 视 $k$ 而定 |

这与既有「43 个 UNSAT 单元」完全吻合。**14MV2 的解法是把雷数放宽**：它 7×7 实测有 7 种雷数（14/15/16/18/20/21/24）。而本地项目 R07 注释写死「难度不靠加大棋盘或改变雷数」—— **这两条设计约定在数学上互斥，必须二选一。**

## 2. 重设计：三轴模型

### 2.1 设计原则

**让每一轴作用在互不相干的数学对象上。**

```
轴 O（Observation 观测）   作用在 f(B)        → 改"看到什么"
轴 S（Structure   结构）   作用在局部模式/拓扑 → 改"雷长什么样"
轴 Z（Conservation 守恒）  作用在低维投影     → 改"雷怎么分布"（可选叠加层）
```

正交性：
- $O \perp S$ —— 观测 vs 布局，两个不同的数学对象，**恒可组合**
- $O \perp Z$ —— 同上
- $S \perp Z$ —— 局部模式 vs 全局计数，**基本正交**（14MV2 左线就是这么做的）
- **唯一会打架的是 Z 轴内部** —— 所以 Z 轴成员必须选代数独立的一组

### 2.2 新 14 个变体

#### 轴 O：观测通道（7 个 + 底座 `classic`）

**准入条件：必须各向同性（$D_4$ 不变），保证与任意 S/Z 算子可组合。**

| 码 | 名称 | 数学定义 $f_p(B)$ | 值域 | 对标 14MV2 | 变动 |
|---|---|---|---|---|---|
| `classic` | 普通 | $\sum_{R_8} B$ | 0–8 | `[V]` | **底座**（不计入 7） |
| `4n` | 四邻 | $\sum_{O_4} B$ | 0–4 | `[X']` 小十字 | 保留 |
| `sc` | 同色 | $\sum_{D_4} B$ | 0–4 | — | 保留 |
| `distsum` | 曼哈顿和 | $1\cdot\sum_{O_4}B + 2\cdot\sum_{D_4}B$ | 0–12 | `[1M]` 多雷 | 保留 |
| `hv` | 纵横双值 | $[\sum_{O_4}B,\ \sum_{D_4}B]$ | 双值 | `[2X]` 十字 | 保留 |
| `loopruns` | 环游程 | 环形序列 $0\!\to\!1$ 上升沿数 | 0–4 | `[1P]` 墙2 | 保留 |
| **`mod3`** | **模三** | $\left(\sum_{R_8}B\right) \bmod 3$ | **{0,1,2}** | **`[2M]` 模运算** | ⭐ **新增** |
| **`liar`** | **误差** | $f_p = \sum_{R_8}B + \varepsilon_p$，$\varepsilon_p\in\{-1,0,+1\}$，撒谎格数量受 $\mathrm{profile}$ 约束 | 0–9 | **`[1L]`/`[2L]`** | ⭐ **新增（难度天花板）** |

**移出 O 轴**：
- `clock`（手性 $C_1$）→ 降级为扩展 Mod / 教学关。若要保留，必须配套"方向基准标记"（如在盘面角标出参考朝向），否则永远无法自由组合
- `fr`（向右射线）→ 同上。`fr` 的 `zero_safe_dirs` 已写死"永不扩散"（`clue_engine.gd:110`），本身就是特例
- `knight` 骑士 → **建议补进 UI**（`rule_registry.gd:99` 已注册，只是没进 `VariantRegistry.definitions()`）。它各向同性，可直接作为第 8 个 O 成员

#### 轴 S：局部结构（7 个 + 底座）

**准入条件：不施加任何对 N 的整除要求（或要求 ≤ 1 个），且作用在局部窗口 / 连通分量上。**

| 码 | 名称 | 数学定义（约束集 $\mathcal{K}$） | 对标 14MV2 | scope | 变动 |
|---|---|---|---|---|---|
| — | 无约束 | $\mathcal{K}=\{0,1\}^{R\times C}$ | `[V]` | — | **底座** |
| **`iso`** | **孤立** | $\forall p:\ B_p=1 \Rightarrow \sum_{R_8(p)}B = 0$ | `[U]` 一元 | POINT | ⭐ 新增 |
| **`pair`** | **成对** | $\forall p:\ B_p=1 \Rightarrow (B_{p-e_x}=1 \lor B_{p+e_x}=1)$ | `[2H]` 横向 | POINT | ⭐ 新增 |
| **`notri`** | **无三连** | 雷与非雷都不能在横/竖构成三连 | `[2T]` | WINDOW | ⭐ 新增 |
| `dense` | 局部密 | $\forall$ 2×2 窗口：$\sum B \le 2$ | （现 `pf`） | WINDOW | **保留改名** |
| **`seg`** | **分段** | $\forall r$：第 $r$ 行恰有 1 段连续雷 | `[2S]` 分段 | ROW | ⭐ 新增 |
| **`conn`** | **连通** | 所有雷构成一个八连通分量 | `[1C]` | ADJ | ⭐ 新增 |
| **`grpk`** | **成组 K** | 每个连通分量大小恰为 $K$（参数化） | `[2G]` 四联 | ADJ+CARD | ⭐ 新增 |

> `grpk` 参数化是关键：`[2G]` 写死 $K=4$ 导致 $4\mid N$ 硬约束（6×6/14 雷直接 UNSAT）。参数化后运行时按 $N$ 选合适的 $K$，UNSAT 自动消失。

#### 轴 Z：全局守恒（可选叠加层，不计入 14）

保留 `mx` / `rl` / `qd` / `4c`，作为第三维**可选勾选**：

- **弃用 `ep`** —— 被 `mx` 严格蕴含，永远不该出现（`RuleSignature` 已按 R4 自动判 forbid）
- **改造 `dt`** —— 改为「部分覆盖」：划分 $k$ 个骨牌后剩余格自由，约束放宽为 $k \le N \le RC-k$，解除 $N=RC/2$ 强制

### 2.3 组合规模对比

| 组合类型 | 旧体系 | 新体系 | 14MV2 参照 |
|---|---|---|---|
| 单变体 | 15 | 14 + 底座 | 14 |
| 一观测 × 一结构（C 类） | 49（**实际大量退化**） | **49（全可用）** | 49（左右线交叉） |
| 双结构（F 类） | 21，其中 2 forbid / 4 warn | $\binom{7}{2}=21$，大概率全可用 | 14MV2 有 `EXTRA_LEFT_COMBINATIONS` 8 组 |
| +Z 叠加层 | — | ×4 | 420 种规则组合 |

## 3. 组合性机械化：`core/rule_signature.gd`

手写的 `global_pair_compat`（`variant_registry.gd:121`）只能答"能不能"，答不了"为什么"，新增算子就要改表。新模块把它变成**可推导**的。

### 3.1 算子签名

每个算子声明

$$\sigma(\mathcal{O}) = (\texttt{obj},\ \texttt{scope},\ \texttt{sym},\ \texttt{div},\ \texttt{implies})$$

| 字段 | 含义 |
|---|---|
| `obj` | 作用对象：`OBS` / `LOCAL` / `TOPO` / `COUNT` |
| `scope` | 作用域：`POINT` / `WINDOW` / `ROW` / `COL` / `REGION` / `ADJ` / `GLOBAL` |
| `sym` | 算子**保持**的对称群（$D_4$ 位掩码） |
| `div` | 对总雷数 $N$ 的整除要求列表 |
| `implies` | 本算子逻辑蕴含的其它算子 id |

### 3.2 五条判据

| 判据 | 规则 | verdict |
|---|---|---|
| **R1** | `obj` 不同 → 跨轴正交 | `ok` |
| **R2** | `obj` 相同且 `scope` 相同 → 可能互锁 | `warn`（需 CP-SAT 复核） |
| **R3** | `sym` 交集为空 → 对称群冲突 | `warn` |
| **R4** | 一方蕴含另一方 → 后者冗余 | `forbid` |
| **R5** | 合并 `div` 对给定 $(size, N)$ 无解 | `forbid`（UNSAT） |

### 3.3 用新判据复算现有冲突

```gdscript
RuleSignature.compat("mx", "ep", Vector2i(6,6), 14)
# -> {verdict: "forbid", reason: "mx 逻辑蕴含 ep，后者完全冗余", rules: ["R4"]}   ✅ 命中原 forbid

RuleSignature.compat("mx", "4c", Vector2i(6,6), 14)
# -> {verdict: "ok", ...}   ⚠ 偶数列下应判冗余（见下方待办）

RuleSignature.compat("qd", "4c", Vector2i(6,6), 14)
# -> {verdict: "forbid", reason: "总雷数 14 不满足整除约束", rules: ["R5"]}      ✅ 精确复现 6x6/14 UNSAT

RuleSignature.compat("mx", "iso", Vector2i(6,6), 14)
# -> {verdict: "ok", reason: "作用对象不同（计数投影 vs 局部结构），天然正交"}
```

**第一个关键验证点**：原有手写的 2 个 forbid + 4 个 warn，新判据能自动导出 6 个中的 5 个，且额外抓到了 `qd+4c` 的真因是整除约束而非"不搭配"。

### 3.4 已知待办

`mx ⟹ 4c` **只在偶数列盘面成立**（$C$ 偶时 $C-1$ 奇，镜像翻转奇偶）。签名表目前没把它写死，因为它是 size-dependent 的。两种改法：

1. 把 `implies` 改成带条件的 `[dst, callable(size)]`
2. 交给生成器 —— 运行时用已有的 `RuleFeasibility.query` / `RuleCpSat.is_feasible` 做 CP-SAT 可行性复核（**推荐**，基础设施现成）

## 4. 为什么新设计能拿到难度天花板

回到上一份报告的结论：**只有 III 族（信息破坏型）能把复杂度推到 16–20。**

| 旧 O 轴成员 | 族 | 天花板 |
|---|---|---|
| classic / 4n / sc / distsum / hv / loopruns / knight | I 邻域线性 | 8–13 |
| clock / fr | I（各向异性） | 8–13，还破坏组合性 |

**旧 O 轴全族 I —— 天花板锁死在 13。**

| 新 O 轴成员 | 族 | 预期天花板 |
|---|---|---|
| `mod3` | II 非线性 | 12–15 |
| **`liar`** | **III 信息破坏** | **16–20** |
| `cipher`（阶段 3） | **III 信息破坏** | **16–20** |

`liar` 的数学结构决定了它的难度：$f_p = \sum_{R_8}B + \varepsilon_p$，求解器必须**先定位撒谎格再解原问题** —— 这是二阶推理，与 14MV2 的 `[2L]` 同构（单步 `GetActualCost` 靠前置链累加到 20）。

3. 跑一遍全 21 组「双结构」组合，对比手写表与新判据的差异

### 阶段 2 —— O 轴去噪（低风险）

4. 把 `clock` / `fr` 从 `definitions()` 移出，改为 `EXTENDED` 分组
5. 把 `knight` 补进 `definitions()`（`KnightRule` 已实现）
6. 实现 `Mod3Rule`（预计 30 行，见下方骨架）
7. 重跑 `tools/batch_all_variants.gd`，验证 49 个 C 类组合的可生成率

### 阶段 3 —— S 轴补全（中风险，需布雷器）

8. 实现 `IsoRule` / `PairRule` / `NotriRule` —— **这三个都可以纯构造式布雷**，不需要 CP-SAT 采样
9. 实现 `SegRule`（行级 DFS，参考现有 `RlRule._rl_dfs`，`rule_registry.gd:799`）
10. `ConnRule` / `GrpKRule` —— 需 union-find 或 CP-SAT 连通性编码，成本最高，放最后
11. 每个新增 S 算子都要实现 `place_mines()`，否则生成器会退化成随机+拒绝采样（违反 R04 红线）

### 阶段 4 —— 天花板（中风险，触及 IR）

12. 实现 `LiarRule` —— 需要给 `RuleBuilder` 加"存在性援助"（撒谎指示变量 + cardinality 约束）
13. 评估 `CipherRule` —— 需要副板（sideboard）支持，14MV2 的经验是**副板是为求解器服务的**（`03_规则系统.md §5.2`），不做副板则 `[2E]` 难度无法准确估计

### 阶段 5 —— 放开 R07

14. 二选一：
    - **方案 A（推荐）**：允许每尺寸 3–5 种雷数，对齐 14MV2 实测（7×7 有 7 种）
    - **方案 B**：维持 R07，但所有 `div` 非空的算子（qd/4c/grpk/dt）按尺寸建立**白名单**，不在白名单的组合直接不生成

## 6. 代码骨架参考

### `Mod3Rule`（最简单的新增，可作为模板）

```gdscript
class_name Mod3Rule
extends RulePlugin

func get_rule_id() -> StringName:
	return &"mod3"

func get_kind() -> String:
	return KIND_CLUE

func describe() -> Dictionary:
	return {"name": "模三", "rule_text": "数字为周围 8 格雷数除以 3 的余数，取值恒为 0/1/2"}

func compute_clue(mine_set: Dictionary, pos: Vector2i, grid_size: Vector2i) -> Variant:
	return count_dirs(mine_set, pos, grid_size, ClueEngine.ring_dirs()) % 3

# 逆向：sum(8 邻) - 3*q == value，q 为辅助整数变量
func build_clue_constraints(b: RuleBuilder, pos: Vector2i, value: Variant) -> void:
	var nbrs := b.neighbors(pos, ClueEngine.ring_dirs())
	var q := b.int_var(0, 3, "mq_%d_%d" % [pos.x, pos.y])
	b.add_eq(b.n_sum(nbrs) - 3 * b.lin_of(q), int(value))

# ★ 关键：模运算下 0 值不再保证邻域安全！0 只说明雷数是 3 的倍数。
func zero_safe_neighbors(_pos: Vector2i, _grid_size: Vector2i, _value: Variant = null) -> Array[Vector2i]:
	return []

func value_upper_bound(_grid_size: Vector2i) -> int:
	return 2
```

> ⚠ `zero_safe_neighbors` 返回空数组是**必须的** —— 这是新增 O 轴算子最容易漏的一处契约（`rule_plugin.gd:82`）。漏了会让连锁扩散把非雷格误判为安全。同理，`loopruns` / `hv` 也各自有非平凡的零值语义，新增时务必显式声明。

### `IsoRule`（最简单的新增 S 算子）

```gdscript
class_name IsoRule
extends RulePlugin

func get_rule_id() -> StringName:
	return &"iso"

func get_kind() -> String:
	return KIND_GLOBAL

func describe() -> Dictionary:
	return {"name": "孤立", "rule_text": "每颗雷的周围 8 格都不能有雷"}

# 构造式布雷：贪心选取与已选集合「互不 8 邻接」的候选格
func place_mines(rng: RandomNumberGenerator, cols: int, rows: int, count: int) -> Array[Vector2i]:
	var chosen: Array[Vector2i] = []
	var blocked := {}
	var cand: Array[Vector2i] = []
	for r in rows:
		for c in cols:
			cand.append(Vector2i(c, r))
	rng.shuffle(cand)
	for p in cand:
		if chosen.size() >= count:
			break
		if blocked.has(p):
			continue
		chosen.append(p)
		for d in ClueEngine.ring_dirs():
			blocked[p + d] = true
	if chosen.size() != count:
		return []   # 构造失败 -> 交由生成器换 seed 重试
	return chosen

func build_global_constraints(b: RuleBuilder) -> void:
	for r in b.rows:
		for c in b.cols:
			var p := Vector2i(c, r)
			var nb := b.neighbors(p, ClueEngine.ring_dirs())
			if nb.is_empty():
				continue
			# B_p => 所有邻居非雷
			b.add_imp(b.cell_var(p), b.not_lit(b.bool_or_of(nb)))
```

**注意**：`iso` 天然限制最大雷数约为 $\lceil R/2\rceil\lceil C/2\rceil$（独立集上界）。5×5 该值 $=3\times3=9 < 10$ ⟹ **5×5/10 雷下 `iso` 数学 UNSAT**。这是又一个 R07 冲突案例，正好印证阶段 5 的必要性。
