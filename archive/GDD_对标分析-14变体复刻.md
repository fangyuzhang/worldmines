## 0. 三条贯穿全文的定律

这三条是从 323,279 条题库与求解器源码中提取出来的，所有设计决策都必须服从：

**定律 1（作用对象守恒）**
线索型永远只改 $f$（观测映射），绝不能碰 $\mathcal{K}$；全局型永远只改 $\mathcal{K}$（可行域），数字恒为原版 8 邻域求和。**这是提示词第五节第 5 条的同义重申，也是全部可组合性的来源。**

**定律 2（约束悖论）**
收紧 $\mathcal{K}$ 会让可行域缩小 ⟹ 单条线索的信息量**上升** ⟹ 定解所需线索数**下降** ⟹ 难度度量反而降低。
只有破坏信息（A 类族 III）才真正提升难度。
> 实证：难度天花板 `[2L]`=20 / `[2E]`=16 / `[2P]`=15，而全部 B 类锁死在 8–13。含 `[2B]` 的占了 20 个极小关卡集中的 13 个。

**定律 3（同类可叠加，但必须有一个信息破坏型参与）**
"线索+线索禁止"是**错的**（实证有 `2E2X`/`2L2M`/`2E2A` 等 10 组）；"全局+全局禁止"也是**错的**（实证有 `EXTRA_LEFT_COMBINATIONS` 8 组）。
真正的规律是：**同类叠加时，其中一条必须是信息破坏型（2E 或 2L），否则题目会因定律 2 而失去难度。**

## 2. 数学模型（全文符号）

雷布局 $B\in\{0,1\}^{R\times C}$，总雷数 $N=\sum B$。

一个变体是一个三元组 $\mathcal{V}=(f,\ \mathcal{K},\ \Pi)$：

| 分量 | 含义 |
|---|---|
| $f_p(B)$ | 线索函数（观测映射），$p$ 为格 |
| $\mathcal{K}$ | 布局硬约束，可行域 $\mathcal{S}=\mathcal{S}_0\cap\mathcal{K}$ |
| $\Pi$ | 可见性策略（开局揭示哪些格） |

**信号集合** $H$（已揭示线索），满足观测的布局集：

$$\mathcal{S}(H)=\{B\in\mathcal{S}\ :\ \forall p\in H,\ f_p(B)=v_p\}$$

| 变体类 | $f$ | $\mathcal{K}$ |
|---|---|---|
| **A 类（线索修改型）** | $f \ne f_{\text{std}}$ | $\mathcal{K}=\{0,1\}^{R\times C}$（**不设限**） |
| **B 类（全局排布型）** | $f=f_{\text{std}}$（原版 8 邻求和） | $\mathcal{K}\subsetneq\{0,1\}^{R\times C}$ |

## 4. 元规则 R

### 4.1 语义（提词定义，实证支持）

1. 开 R 后：**去掉"总雷数"条件 ⟹ 必有 $\ge 2$ 个合法解**
2. 开 R 后：**唯一解必须依赖总雷数推理才能锁定**
3. R **不改地雷规则、不改数字公式**，只改谜题的推理前提
4. R 可叠加于：单变体 / 加强 / `[+]` / `[#]` / `[&]`

### 4.2 实现规格（对齐 MV2 源码）

R 不是布尔开关，而是**两条可选参与的约束**，各自带代价：

```csharp
// AddBombCountConstraint(num, difficultyScaler: 4, costLimit: 4)
for (int k = 4; k < num; k += 4) {                 // k = 4, 8, 12, 16
    constraints.Add(new Constraint(intExpr >= k, $"[R>={k}]", 1, ...));   // 阶梯，各 Cost=1
    if (list2.Count >= 4) break;                    // 最多 4 级
}
constraints.Add(new Constraint(intExpr == num, "[R]",
    (num - 1) / 4 + 1 - list2.Count, ...));
```

$$\mathrm{Cost}\big([R]\big)=\Big\lfloor\frac{N-1}{4}\Big\rfloor+1$$

| 尺寸 / 雷数 | `[R]` 代价 | 该尺寸噩梦档 MIN | 能否单独达标 |
|---|---|---|---|
| 5×5 / 10 | 3 | 5 | 否 |
| 6×6 / 14 | 4 | 5 | 否 |
| 7×7 / 20 | 5 | 6 | 否 |
| 8×8 / 26 | **7** | 6 | **能**（但被平衡闸拦） |
| 8×8 / 32 | 8 | 6 | 能 |

### 4.3 ★ 负复杂度＝R 标记（提词第四节第 4 步的落地方式）

MV2 用**复杂度取负**来标记"这一步动用了 R"：

$$\text{若该步使用了 }[R]\text{ 或 }[R{\ge}k]\ \Rightarrow\ c_{\text{step}} \leftarrow -|c_{\text{step}}|$$

> **注意**：负号 **≠ 必须猜测**。实证：唯一取负条件就是 `Name.StartsWith("[R]") || Name.StartsWith("[R>=")`（`[05 §3.5]`）。旧文档中"负复杂度＝需猜"的结论已被推翻。

于是「关闭总雷数 ⟹ 必多解」这条校验，在实现上就是：

```text
剔除所有 [R] / [R>=k] 约束 → 重新求解
若仍有唯一解  → 该题不满足 R 语义，作废
若解数 >= 2   → R 校验通过
```

### 4.4 R 的平衡闸（防止全靠 R）

$$L(p)=\sum_{c>0}\big(c=1\,?\,1:10^{c}\big)\cdot n_c,\qquad G(p)=\sum_{c\le0}10^{|c|}\cdot n_c$$

$$\text{通过条件：}L(p) > G(p)$$

刻意的不对称：复杂度 1 的逻辑步记 $10^0=1$，而 $|c|=1$ 的 R 步记 $10^1=10$ ⟹ **一次"动用总雷数"需要 10 次"一眼可见"来抵消**。
实测违规率：普通 **0.00%** ｜ 困难 **0.63%** ｜ 噩梦 **3.96%**。

## 5. 组合容器

### 5.1 `[+]` 双变体

**纠正提词的禁止项**（见 §0 定律 3），改为**白名单 + 必含条件**：

| 组合 | MV2 实证 | 规则 |
|---|---|---|
| A + B | `2E1M` `2L1X` `2E1L` `2L1M` `2E1W` `2L1E` `2E1X` `2L1N` `2E1E` `2L1P`（跨代 10 组） | ✅ **主流形态**，无条件允许 |
| A + A | `2E2X` `2E2D` `2E2M` `2E2A` `2E2P` `2L2X` `2L2D` `2L2M` `2L2A` `2L2P` | ✅ 允许，**但必含 `2E` 或 `2L`** |
| B + B | `EXTRA_LEFT_COMBINATIONS` 8 组：`2G2H` `2C2H` `2C2G` `2F2G` `2F2H` `2C2F` `2B2H` `2G2R` | ✅ 允许，**同时需通过 §6.4 的正交判据** |

> 即：**不是禁止，而是要满足 §6.4 的代数独立性判据。** 提词的"禁止线索+线索"应理解为"禁止**无信息破坏型参与**的 A+A"。

### 5.2 `[&]` 双棋盘

**修正几何方向**：MV2 的副板在**右侧**，不是上下。

```csharp
public bool HasExpectedSideboardWidth => SizeY == SizeX * (UsesSeparateSideboards ? 3 : 2);
```

| 形态 | 判定 | 实测 |
|---|---|---|
| 主板 + 1 副板 | `宽 == 高 × 2` | 5×10 / 6×12 / 7×14 / 8×16 |
| 主板 + 2 副板 | `宽 == 高 × 3` 且含 `[&&]` | 5×15 / 6×18 / 7×21 / 8×24 |

**双板结构确证**：全部 158,535 条 $2W$ 记录中，**左半（主板）的雷计数 100% 等于关卡名声明的雷数**，右半另有独立雷数。
（例：`[1B][2E]!5x10-10-1608` → 主板 10 雷、副板 5 雷）

**副板偏移常量**：`DistinctColumnSumBoardOffset = SizeX`、`DistinctRowSumBoardOffset`、`GuessBoardOffset`、`LiarBoardOffset`

**★ 副板的设计目的（开发者自述）**：
> "副板的概念最初从 `[2E]` 加密产生 —— 在没有副板时，求解器无法准确估计 `[2E]` 谜题的难度。"
> `ui_zh_CN.txt:215-218`

**副板是为求解器服务的，不是为玩法服务的。** 做 `[&]` 时若不做难度评估侧的实现，`2E` 类副板关卡的难度标注必然失真。

| `[-]` | **该题不参与难度计算** |

> 提词中的 `[$]` 若指"纸笔"是对的；但若写成 `[-]` 需注意后者是"不参与难度计算"，二者不可混淆。

## 6. 关卡语法与生成器规格

### 6.1 正式文法

```
<Level>     ::= <Size> '-' <Mines> '-' <RuleExpr> [ '-' <SolutionSummary> ] '-' <Id>
<Size>      ::= <H> 'x' <W>
<RuleExpr>  ::= <Modifier>* <Term> ( '+' <Term> )?   |  <TagMap>
<Term>      ::= <RuleCode> [ "'" [ "'" ] ] [ '^' ]
<RuleCode>  ::= 'V' | A类7码 | B类7码 | '2U' | '2Z' | '2I'
<Modifier>  ::= '[@c]' | '[@cf]' | '[@s]' | '[@h]' | '[@v]' | '[$]' | '[-]' | 'R' | '[&&]'
<SolutionSummary> ::= '(' ( <c> 'x' <n> ) ( ',' <c> 'x' <n> )* ')'
```

**实例**（真实题库格式）：

```
[1B][2A]!5x5-10-(4x2,3x1,2x1,1x4;L4R4)-1636
        │   │  │  │              │        └ 谜题编号（0–7999）
        │   │  │  │              └ L4=第4行R4=第4列为偏差格（2L 语义）
        │   │  │  └ SolutionSummary：8 步中 2 步 c=4、1 步 c=3、1 步 c=2、4 步 c=1
        │   │  └ 10 雷
        │   └ 5x5
        └ ! = 困难档（!! = 噩梦档）
```

### 6.2 单步复杂度算法（难度生成器核心）

```
hitSetSize = 1
while true:
    约束 cellHit.CountTrue() == 1            // 恰好推出 1 个新格
    for each 候选约束 l:
        repeat Cost(l) times: 塞入 l          // ★ 按代价重复，而非按条数
    Ensure(总代价 == hitSetSize - 1)          // 钉死预算
    if FindAnswer(): break                    // 可满足 → 最小线索数 = hitSetSize
    hitSetSize += 1
c_step = MAX over used constraints of GetActualCost(c)     // ★ MAX 不是 SUM
```

$$\mathrm{GetActualCost}(C)=\min_{P\in\mathrm{PrereqAlts}(C)}\Big(\mathrm{Cost}(C)+\sum_{c\in P}\mathrm{Cost}(c)\Big)$$

前置关系构成 **DAG**，成环即抛 `InvalidOperationException("Cyclic constraint prerequisite...")`。

### 6.4 生成器 4 步校验（落地版）

提示词的 4 步，逐条映射到可执行实现：

| # | 提示词要求 | 实现 |
|---|---|---|
| 1 | 约束叠加校验 | 全部规则插件的 `build_*_constraints` 并集；任一 `Infeasible` 即弃 |
| 2 | 布局合法性校验 | `RuleSignature.compat_all()` 静态判据（R1–R5）+ CP-SAT `is_feasible` 运行期复核 |
| 3 | 唯一解校验 | 序贯 forced-cell 演绎（本地已有 R01 红线）**优于**静态解数 $=1$ |
| 4 | R 专项校验 | 剔除 `[R]`/`[R>=k]` 重解 → 必须多解；还原后必须唯一 |

**为什么第 3 步用序贯而非静态唯一解**（本地项目的重要认知，应保留）：

> 静态多解是**正常现象**（0 值格不进初始线索、带遮蔽的规则关卡必然静态多解）。用静态唯一会误杀。真正的红线是**序贯无猜**：每回合必须有可演绎的强制格，直到全盘确定。

### 6.5 代数独立性判据（`core/rule_signature.gd`，已交付）

替代手写互斥表。签名 $\sigma=(\text{obj},\text{scope},\text{sym},\text{div},\text{implies})$：

| 判据 | 规则 | verdict |
|---|---|---|
| R1 | `obj` 不同 → 跨类正交 | `ok` |
| R2 | 同类且 `scope` 相同 → 可能互锁 | `warn`（需 CP-SAT 复核） |
| R3 | `sym` 交集为空 → 对称群冲突 | `warn` |
| R4 | 一方蕴含另一方 → 冗余 | `forbid` |
| R5 | 合并 `div` 对给定 $(size,N)$ 无解 | `forbid`（UNSAT） |

> 已验证：此项主体quiries 能自动导出 MV2 式的合法性结论，并精确复现「6×6/14 雷下 `qd` UNSAT」这类整除冲突。

### 必做的两项基础改动

**(1) 放宽 R07 固定雷数**

MV2 实测 5×5 有 4 种雷数、7×7 有 7 种。约束越紧，越必须允许非标准雷数，否则 `qd`（需 $(N-c)\bmod4=0$）、`4c`（需偶数）、`grpK`（需 $K\mid N$）会大面积 UNSAT。

建议：`level_spec.gd` 改为返回**候选雷数列表**，生成器在列表中逐个试。

**(2) RuleBuilder 扩展“存在性”原语**

`2E`（未知双射）、`2L`（未知偏差位）、`2I`（未知缺失方向）都需要：
 辅助指示变量 + exactly-one / cardinality 约束 + unsat_core 提取。
现有 `sum/wsum/lin/add_eq/add_le/add_imp/add_bool_or` **不足以直接表达**，需补 `add_exactly_one` / `add_alldiff`。**这是打通 A 类 7 个变体的前置任务。**
