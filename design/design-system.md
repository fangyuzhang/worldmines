## 0. 审计先行：为什么必须重做 Token

对源码里 **12 套主题**的真实色板跑了全配对对比度审计，**26 项不达 WCAG AA**，其中两个是系统性问题：

| 问题 | 范围 | 最差实例 |
|---|---|---|
| **次级文字用于小字号正文** | 12 套里 **9 套**不达标 | `cozy_mist` **2.58:1**（需 4.5） |
| **强调色直接当文字色用在浅底上** | **12 套全部**不达标 | `cozy_salt` **3.06:1**（需 4.5） |
| 未翻格上的文字 | `cozy_prism` | **1.13:1** —— 等于看不见 |
| 旗标（非文本） | `dark` | **2.41:1**（需 3.0） |

**根因不是"颜色不好看"，是 token 语义缺失**：
- 只有 `accent` 一个角色，它既要当**面**（按钮底色）又要当**墨**（浅底上的字）——物理上不可能同时满足。
- `text_secondary` 用"把主文字调浅"来表达层级，但调浅必然牺牲对比度。

### 修法（算法，非手调）

新增两个语义 token，并**保持原色相与饱和、只压明度**直到达标（脚本 `design/fix_tokens.py`，结果可复现）：

```
accent      → 面：按钮底、大面积图形（保持原值）
accent-ink  → 墨：强调色文字/图标，用在 bg / card 上（新，压暗）
text-secondary → 小字号次级文字（新值，压暗）
```

| 主题 | text-secondary | accent-ink | 达标比值 |
|---|---|---|---|
| cozy_salt | `#5b6471` → **`#4b525d`** | `#3471a1` → **`#28567a`** | 4.56 / 6.66 |
| cozy_terracotta | `#665a55` → **`#584e49`** | `#9a5b32` → **`#734425`** | 4.66 / 5.53 |
| cozy_sage | `#5c6c6b` → **`#4c5958`** | `#2e7f67` → **`#23614f`** | 4.62 / 6.30 |
| cozy_dusk | `#645a6d` → **`#524a59`** | `#7f4bc2` → **`#61359b`** | 4.53 / 6.66 |
| cozy_mist | `#657b8c` → **`#455460`** | `#3f6d8e` → **`#31556e`** | 4.63 / 6.66 |
| cozy_oat | `#8f7959` → **`#695942`** | `#7c6a45` → **`#68593a`** | 4.66 / 5.91 |
| dark | 不变（已达标） | 不变 | 7.87 / 6.95 |

> 12 套完整值见 `design/tokens.json`。

## 1. 设计原则

1. **棋盘是唯一主角** —— chrome 让位。所有常驻 UI 的高度预算是硬约束（见 §3）。
2. **只读与可点必须可区分** —— 读数用「无底、无边框、等宽数字」；操作一律「有底、有投影、可聚焦」。玩家不该去点一个数字。
3. **颜色承担语义，不承担装饰** —— 每个色都有唯一职责和一个实测比值。
4. **用层表达层级，不用跳页** —— 查阅是覆盖，不是离开；对局状态永不因看东西而丢失。
5. **状态永远可见** —— 任何时刻都能回答：还剩多少雷 / 能不能撤销 / 现在该做什么。
6. **无障碍是一等公民** —— 不是事后补丁（见 §5）。

## 2. Token 系统

### 2.1 色彩（语义命名，不是外观命名）

| Token | 职责 | 约束 |
|---|---|---|
| `--bg` | 页面底 | — |
| `--card` | 浮起面 | 与 `--bg` 有可辨明度差 |
| `--sunken` | 下沉面（输入、分段底） | 与 `--card` 反向 |
| `--cell-hidden` / `--cell-revealed` | 棋盘两态 | 两态本身需可辨 |
| `--text` | 正文 | on bg ≥ 4.5，on card ≥ 4.5 |
| `--text-secondary` | **小字号**次级 | on bg ≥ 4.5（**这是旧版失败点**） |
| `--accent` | **面**：按钮底、填充 | 与其上的 `--accent-text` ≥ 4.5 |
| `--accent-ink` | **墨**：浅底上的强调文字/图标 | on bg ≥ 4.5，on card ≥ 3.0 |
| `--danger` / `--safe` | 语义状态 | 非文本 ≥ 3.0 |
| `--line` | 分隔与描边 | 非文本 ≥ 3.0（或纯装饰） |
| `--n1`…`--n8` | 数字 1–8 | 大字号 on `--cell-revealed` ≥ 3.0 |

**关键规则**：`accent` 与 `accent-ink` **不可互换**。底上用 `accent`，字上用 `accent-ink`。

### 2.2 字号阶梯（1.25 模数）

| Token | 值 | 用途 |
|---|---|---|
| `--fs-xs` | 11.5px | 角标、徽章 |
| `--fs-sm` | 13px | 次级说明（配 `--text-secondary`） |
| `--fs-base` | 15px | 正文 |
| `--fs-md` | 17px | 读数 |
| `--fs-lg` | 19px | 区块标题 |
| `--fs-xl` | 24px | 页面标题 |
| `--fs-2xl` | 30px | 结果 |
| `--fs-num` | cell × 0.56 | 棋盘数字（随格子缩放） |

字重只用 **600 / 700**（圆体在小字号下 400 偏细）。

### 2.3 间距（4 基准）

`4 · 8 · 12 · 16 · 24 · 32 · 48 · 64`
棋盘区用 11（= 垫子内缩，与瓦片圆角视觉配平，故意破格）。

### 2.4 层级（阴影）

| Token | 值 | 用途 |
|---|---|---|
| `--sh-1` | `0 2px 0 sh2` | 按钮常态（硬投影，给"实体感"） |
| `--sh-2` | `--sh-1 + 0 5px 14px` | 卡片 |
| `--sh-3` | `0 9px 26px` | 棋盘垫子（唯一"抬起"的元素） |
| `--sh-4` | `0 20px 46px` | 模态 |

**规则**：同一元素只用一个层级；棋盘垫子是全屏最高层级（它是主角）。

### 2.5 动效

| Token | 值 | 用途 |
|---|---|---|
| `--mo-fast` | 120ms | hover / 按下 |
| `--mo-base` | 220ms | 翻开、层滑入 |
| `--mo-slow` | 320ms | 主题过渡 |

缓动：进入 `cubic-bezier(.2,.9,.3,1.2)`（轻微回弹），退出 `ease`。
**全部动效在 `prefers-reduced-motion: reduce` 下退化为即时**（§5）。

## 3. 布局与高度预算

旧版把 64+64=128px 给了 chrome，棋盘只剩 57px 格。新版**按"出现时机"分配**：

| 层 | 高度 | 出现时机 | 内容 |
|---|---|---|---|
| L1 读数带 | **40px** | 常驻 | 雷数 / 计时 / 可断定 / 进度条（**无 logo 无导航**） |
| L0 棋盘区 | 弹性 | 常驻 | 棋盘 + 垫子（主角） |
| L2 上下文条 | **58px** | 常驻 | 只显示"此刻能做的事"，随状态增删 |
| L3 查阅层 | 覆盖 | 我要看时 | 左拉手=全局导航 / 右拉手=本局信息 |
| L4 打断层 | 覆盖 | 必须处理 | 仅确认；**结算改为棋盘下方结果带** |

**结果**：对局中格边长 **57px → 66px（+16%）**。

## 4. 组件库

### 4.1 按钮 `Button`
| 变体 | 底色 | 字色 | 用途 |
|---|---|---|---|
| Primary | `--accent` | `--accent-text` | 一屏仅一个（主行动） |
| Default | `--card` | `--text` | 常规操作 |
| Danger | `--danger` | `#fff` | 破坏性，必须二次确认 |
| Ghost | 透明 | `--text-secondary` | 低优先 |

状态：default / hover（上浮 1px + 换 accent 底）/ active（下沉 1px）/ **focus-visible（3px accent 环，offset 2px）** / disabled（opacity .42，`pointer-events:none`）
尺寸：`md` 40px / `sm` 34px —— **触达 ≥44px 由外层 padding 补足**（§5）

### 4.2 读数 `Readout`
**只读**：无底、无边框、`font-variant-numeric: tabular-nums`、`cursor: default`。
与按钮形成**视觉语法上的对立**——玩家扫一眼就知道哪个能点。

### 4.3 平板瓦片 `Tile`
- 圆角 `cell × 0.106`，缝 `cell × 0.064`（沿用源码比例）
- 未翻：凸起（顶部内高光 + 底部硬投影）
- 已翻：凹陷（顶部内阴影）
- **数字 = 跨列等宽**，避免翻动时字宽跳变
- 键盘光标：3px accent 环

#### ⚠️ 深色模式的硬约束（重要设计决策）

深色模式下有 **4 个面层**（页面底 / 棋盘垫子 / 未翻瓦片 / 已翻瓦片）需要互相可辨。
实测结论：**在暗部不存在满足"两两 ≥1.25"的解**。

原因是对比度公式里的 `+0.05` 项：亮度越低，可用的对比度空间被压得越扁。
穷举 `#101014–#4c4c59` 区间内全部组合，1.25 阈值下**无解**。

**处理方式（设计决策，不是妥协）**：深色模式下**状态差异由描边承载**，而不是填充明度差 ——

```css
.app[data-theme="dark"] .tile      { border:1px solid rgba(255,255,255,.15) }
.app[data-theme="dark"] .tile.open { border-color:rgba(0,0,0,.45) }
```

并同时补上顶部内高光/内阴影（§2.4 层级）+ 字形（数字或空白）三重编码 ——
**任何状态都不靠单一维度表意**，这也是 §5「不靠颜色单独表意」的延伸。

因此深色主题的面层取值不追求"拉开"，而是：
`bg #141419` → `mat #2e2e38` → `未翻 #454551` / `已翻 #232328`，差不足处由描边补足。


### 4.4 层 `Panel`
左/右拉手滑入，`--mo-base` 缓动，带 scrim（点击关闭）。
**内容滚动而非整层滚动**，标题固定。

### 4.5 空状态 `Empty`
图标 + 一句解释 + **一个出口动作**（不是干瘪的"暂无数据"）。

## 5. 无障碍（WCAG 2.1 AA）

| 项 | 措施 | 验证方式 |
|---|---|---|
| **对比度** | 全部 token 达 AA | ✅ `design/contrast_audit.py --html design/ui.html` 实测 0 失败 |
| **键盘可达** | 全部可交互元素可 Tab；`focus-visible` 3px 环；对局内方向键/WASD 走格、`F` 插旗、`Enter` 翻开 | ✅ 逻辑测试覆盖 |
| **触达 ≥44px** | 图标按钮 44×44；上下文条按钮 min-height 44（视觉 40 + 外扩） | 人工 |
| **语义化** | `role="switch"` + `aria-checked`；`aria-pressed`；`aria-current`；按钮用真 `<button>` | 代码审查 |
| **动效敏感** | `prefers-reduced-motion: reduce` → 全部 animation/transition 归零 | 代码审查 |
| **文本缩放 200%** | 布局用 flex/grid + `rem`/比例，不写死宽高 | 人工 |
| **不靠颜色单独表意** | 旗/雷/数字**另有形状与字形**区分；危险色同时配文案 | 人工 |

## 6. 响应式

| 断点 | 策略 |
|---|---|
| ≥1024px | 完整布局，左右拉手在屏幕两侧 |
| 768–1023px | 拉手收窄为 20px；导航文字隐藏只留图标 |
| <768px | 宠物隐藏（纯装饰让位）；上下文条横向滚动；读数带合并「可断定」 |

棋盘始终 `min(可用宽, 可用高)` 取小 —— **保证格子永远正方形**，这是扫雷的硬要求。
